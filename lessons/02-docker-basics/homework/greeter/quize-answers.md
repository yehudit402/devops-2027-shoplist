# סיכום לימוד: DevOps ו-Docker (שיעורים 1 ו-2)

המסמך כולל את 18 שאלות הבוחן, ולצד כל שאלה את התשובה והעיקרון שמאחוריה, כפי שעברנו עליהם.

---

## חלק א: DevOps ומיקרו-סרוויסים (שיעור 1)

**1. מה המשפט הכי מדויק על DevOps?**


**תשובה: ג.** DevOps היא תרבות עבודה של צוות שלם שאחראי על הקוד לכל אורך הדרך, ולא תפקיד של אדם בודד ולא כלי.

**2. "סימנו את גרסה 1.2 כמוכנה לעלות לשרת". לאיזה שלב בלולאה זה שייך?**

**תשובה: ב (Release).** ב-Release מסמנים גרסה כמוכנה ליציאה. ב-Build יוצרים חבילה שאפשר להריץ, ב-Deploy מעלים בפועל לשרת, וב-Operate מפעילים ומנטרים.

**3. באפליקציה מונוליטית יש באג שמפיל את דף התשלום. מה קורה?**

**תשובה: ב.** במונולית כל החלקים רצים כתהליך אחד, ולכן אין בידוד תקלות.

**4. איך שני מיקרו-סרוויסים מדברים זה עם זה?**

**תשובה:** דרך הרשת, בבקשות HTTP ל-API של הסרוויס השני. כל פנייה דורשת כתובת: שם הסרוויס, פורט ונתיב, למשל `GET http://backend:5000/stats`.

**5. ב-ShopList, למי פונה הדפדפן?**

**תשובה: ג.** רק ה-frontend חשוף למשתמש, כדי להקטין את משטח התקיפה. השרשרת: דפדפן, frontend, backend, postgres.

**6. למה stats לא צריך את הסיסמה של מסד הנתונים?**

**תשובה:** כי הוא לא מדבר ישירות עם מסד הנתונים. הוא פונה ל-backend, וה-backend הוא היחיד שמתחבר למסד. זהו עקרון מינימום ההרשאות: כל סרוויס מקבל רק מה שהוא צריך, וכך פריצה לסרוויס אחד לא חושפת את הסיסמה.

**7. תן חיסרון אחד של מיקרו-סרוויסים.**

**תשובה:** מורכבות. יש הרבה סרוויסים לבנות, להעלות, לנטר ולנהל, והתקשורת ביניהם עוברת ברשת, שיכולה להיכשל או להיות איטית.

## חלק ב: Docker (שיעור 2)

**8. מה ההבדל בין image ל-container?**

**תשובה:** image הוא חבילה מוכנה (קוד, תלויות והגדרות) שאינה רצה. container הוא מופע שרץ בפועל ונוצר מה-image. מאותו image אפשר להריץ כמה containers.

**9. מחקתי container עם `docker rm`. מה קרה ל-image שלו?**

**תשובה: ב.** ה-image נשאר. מחיקת image נעשית בפקודה נפרדת, `docker rmi`.

**10. container לעומת מכונה וירטואלית. מה נכון?**

**תשובה: ב.** מכונה וירטואלית מריצה מערכת הפעלה שלמה ולכן כבדה ואיטית לעלות.

**11. בפקודה `docker run -p 8080:80 nginx:1.30-alpine`, מה המספר 8080?**

**תשובה:** הפורט במחשב המארח, שדרכו ניגשים מבחוץ (`http://localhost:8080`). Docker מעביר את הפניות לפורט 80 בתוך ה-container. הסדר הוא תמיד מחשב:container. שני containers לא יכולים לתפוס את אותו פורט חיצוני.

**12. מה עושה `EXPOSE 5000` ב-Dockerfile?**

**תשובה: ב.** זה תיעוד בלבד. כדי לפתוח פורט בפועל צריך `-p` ב-`docker run`.

**13. למה מעתיקים את `requirements.txt` ומתקינים את התלויות לפני שמעתיקים את `app.py`?**

**תשובה:** Docker שומר כל שורה ב-Dockerfile כשכבה (cache). כששכבה משתנה, כל השכבות שאחריה נבנות מחדש. הקוד משתנה לעתים קרובות והתלויות לעתים רחוקות, ולכן שמים את התלויות קודם. כך שינוי ב-`app.py` לא מבטל את שכבת ההתקנה השמורה, והבנייה מהירה.

**14. למה השרת בתוך container מאזין ל-`0.0.0.0` ולא ל-`localhost`?**

**תשובה:** בתוך container, `localhost` הוא ה-container עצמו, והבקשות מהדפדפן מגיעות אליו מבחוץ. שרת שמאזין רק ל-`localhost` לא יענה להן. `0.0.0.0` מאזין לכל כתובות הרשת, ולכן עונה גם לבקשות מבחוץ.

**15. למה הקוד של ה-backend קורא את הסיסמה ממשתנה סביבה ולא כותב אותה בקוד?**

**תשובה:** קוד נשמר ב-Git ומועלה ל-GitHub, וכל מי שיש לו גישה לקוד רואה את הסיסמה, גם בהיסטוריה הישנה. משתנה סביבה נקבע מחוץ לקוד בזמן ההרצה (`-e DB_PASSWORD=...`), ואפשר להחליף אותו בלי לבנות image מחדש.

**16. הרצתם את stats לבד. `/health` מחזיר 200, ו-`/stats` מחזיר 502. למה?**

**תשובה:** `/health` בודק רק ש-stats עצמו חי. `/stats` צריך לפנות ל-backend כדי לקבל נתונים, וכשמריצים את stats לבד ה-backend לא קיים. הפנייה נכשלת ו-stats מחזיר 502 (Bad Gateway).

**17. מה ההבדל בין `docker stop` ל-`docker rm`?**

**תשובה:** `docker stop` עוצר container שרץ, והוא ממשיך להתקיים ואפשר להפעיל אותו שוב עם `docker start`. `docker rm` מוחק את ה-container לגמרי. ה-image נשאר בשני המקרים.

**18. ב-`docker run hello-world` לא כתבנו גרסה. מה Docker הוריד, ולמה זה לא מתאים לסרוויס אמיתי?**

**תשובה:** Docker הוריד את התג `latest`, הגרסה האחרונה. זה לא מתאים לסרוויס אמיתי כי הגרסה משתנה עם הזמן, ועדכון עלול לשבור את הקוד או לגרום לסביבות שונות להריץ גרסאות שונות. לכן מצמידים גרסה מפורשת, למשל `nginx:1.30-alpine`.
